\subsection*{A04P: Practical Problems}
\begin{description}
\item{\bf A04P.1} \emph{Lottery scheduling} is a scheduling discipline where each task is assigned a number of tickets. To decide which task
to execute, the scheduler randomly selects a ticket (under a uniform distribution), and the task owning the ticket is allowed to
execute. A lottery scheduler can be either \emph{pre-emptive}, in which a task can only execute for a certain amount of time
before being interrupted, or \emph{non pre-emptive} if a task always executes to completion once selected.
\begin{enumerate}[label=\alph*)]
\item Construct a PRISM model of a pre-emptive lottery scheduler with three clients, where each task is given a single ticket, and the
quantum (the length of time before a task is interrupted) is one time unit. You will have to decide on an appropriate way to model the
tickets, which means deciding on an appropriate level of abstraction.
%
\ifwithanswers
\color{blue}
\par
\textbf{Modelling Choices for the Pre-emptive Lottery Scheduler}
\begin{itemize}
    \item \textbf{Ticket Assignment:} At job creation, the scheduler deterministically assigns 1 ticket to the new job. This explicit step makes the model flexible for different assignment methods in following exercises.
    \item \textbf{Job Length:} Upon creation, each job randomly and uniformly selects an execution length between 1 and 5 time units.
    \item \textbf{Execution Logic (1-unit quantum):} Jobs with at least one ticket are eligible to run. The CPU is granted to the job with the highest ticket count. For three jobs ($j_1, j_2, j_3$), the scheduling guards are:
    \begin{itemize}
        \item $tickets(j_1) \geq tickets(j_2) \land tickets(j_1) \geq tickets(j_3) \rightarrow j_1$ executes.
        \item $tickets(j_2) \geq tickets(j_1) \land tickets(j_2) \geq tickets(j_3) \rightarrow j_2$ executes.
        \item $tickets(j_3) \geq tickets(j_1) \land tickets(j_3) \geq tickets(j_2) \rightarrow j_3$ executes.
    \end{itemize}
    \item \textbf{Non-Determinism and Ties:} Because jobs can have equal tickets, guards overlap. This non-determinism is naturally resolved by PRISM's underlying uniform distribution, which simulates a fair lottery draw among the tied jobs.
\end{itemize}
\color{black}
